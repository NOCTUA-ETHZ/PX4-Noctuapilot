# Winsen ZE07-H2 hydrogen sensor

The `ze07_h2` UART driver is compatible with the existing `dfrobot_gas` output
on Noctua's `flash_v1.17` branch. It publishes the existing
`sensor_gas_concentration` uORB topic, so the existing `NOCTUA_GAS_SENSOR`
MAVLink stream can forward it without a dialect or groundstation message change.
The DFRobot driver remains available.

## Output compatibility

| Field | ZE07-H2 output |
| --- | --- |
| `timestamp` | PX4 publication time, microseconds since boot |
| `timestamp_sample` | Packet receipt time, microseconds since boot |
| `device_id` | Serial device ID, ZE07-H2 device type `0xF1`, UART number |
| `concentration_ppm` | Hydrogen concentration in ppm; no percent/LEL conversion |
| `temperature` | `NaN`: the documented UART protocol does not expose temperature |
| `gas_type` | `GAS_TYPE_H2 = 5`, matching the existing DFRobot H2 output |

The sensor's wire gas code `0x06` is converted to the uORB H2 enum `5`.
One ZE07-H2 instance is supported. DFRobot and ZE07-H2 can run together on
separate interfaces; each gets a uORB instance and distinct device ID.
Do not assume that the ZE07-H2 will always be instance 0 when both run.
Consumers must tolerate `NaN` temperature and check sample freshness.

## Wiring

Use the pin numbering in the [Winsen manual](https://www.winsen-sensor.com/d/files/manual/ze07-h2.pdf),
not connector colours or an assumed cable orientation.

| ZE07-H2 pin | Connection |
| --- | --- |
| 15, Vin | Regulated 5 V supply (module specification: 5–12 V) |
| 5 or 14, GND | Common ground with the Pixhawk |
| 8, TXD | RX of an unused Pixhawk UART |
| 7, RXD | Optional: Pixhawk TX through a suitable 3.3 V → 3.0 V level interface |

Winsen specifies 0–3.0 V UART levels. The optional return connection needs a
compatible voltage level; the manual does not specify a 3.3 V tolerant RX.
The default initiative-upload mode works with only power, ground, and sensor TX.
With RX connected, the driver requests initiative-upload mode at startup and
retries after a data outage; this also recovers a module left in Q&A mode.
The UART is fixed at **9600 baud, 8 data bits, no parity, one stop bit**.
Do not share this physical UART with MAVLink, a companion, GPS, or the fuel cell.

This driver implements the documented UART interface, not analog voltage or I2C.
If your carrier board has SDA/SCL labels, verify its exact model/protocol before
wiring it as I2C; the linked ZE07-H2 manual does not specify an I2C interface.

## Build and enable

The change enables `CONFIG_DRIVERS_GAS_SENSOR_ZE07_H2=y` in
`boards/px4/fmu-v6c/default.px4board`. Other targets need this option enabled.
In your configured PX4 build environment:

```sh
make px4_fmu-v6c_default
```

Flash the newly built `build/px4_fmu-v6c_default/px4_fmu-v6c_default.px4`.
The old prebuilt `.bin` in the repository root does not include this driver.

Set **SENS_ZE07_CFG** to an unused port in QGroundControl, then reboot.
The default is Disabled. Port values for the Pixhawk 6C in this branch:

| Port | `SENS_ZE07_CFG` | Device |
| --- | --- | --- |
| TELEM1 | 101 | `/dev/ttyS5` |
| TELEM2 | 102 | `/dev/ttyS3` |
| TELEM3 | 103 | `/dev/ttyS1` |
| GPS1 | 201 | `/dev/ttyS0` |
| GPS2 | 202 | `/dev/ttyS6` |

Free the selected port in the configuration of any previous user first.
The driver sets its baud rate itself; no `SER_*_BAUD` change is needed.
For example, **only if TELEM2 is unused**, run in the QGC MAVLink Console:

```sh
param set SENS_ZE07_CFG 102
param save
reboot
```

If replacing the DFRobot sensor, set `SENS_EN_DFGAS` to `0` before reboot.
If retaining both sensors, leave it enabled.

For a manual bench start on an unused TELEM2 instead of autostart:

```sh
ze07_h2 start -d /dev/ttyS3
ze07_h2 status
listener sensor_gas_concentration
ze07_h2 stop
```

These commands run on the Pixhawk, not in a Raspberry Pi/Linux shell.
If both sensor drivers are running, select the relevant listener instance
(e.g. `listener sensor_gas_concentration -i 1`).

## Startup and data loss

`SENS_ZE07_WARM` defaults to 300 seconds. Valid packets are counted during warm-up
but not published. The manual lists up to three minutes warm-up and recommends
at least five minutes on first use. The driver cannot read a sensor-ready flag.
The delay is measured from UART initialization; it restarts on a UART reopen
or the first valid packet after a gap exceeding five seconds.

Expect approximately one publication per second after warm-up. `status` shows
valid/invalid packet counts, UART errors, and the last published sample's age.
A status of "waiting for valid data / warming up" with increasing valid-packet
counts confirms serial reception while publication is inhibited.

`SENS_ZE07_WARM=0` is available for an emulator or an already warmed bench sensor.
Restart the driver after changing it; restore 300 for normal operation.

Missing or corrupt data never produces a synthetic zero reading or a refreshed
old measurement. The last uORB sample remains stored with its original timestamp;
subscribers must detect stale data. The driver does not add flight failsafes.

## Protocol checks and validation

Only complete nine-byte initiative-upload packets with a valid checksum, H2 gas
code, ppm units, zero decimal places, and 30000 ppm full scale are accepted.
Concentrations above the reported range are rejected. The parser handles noise,
fragmented reads, consecutive packets, and embedded `0xff` bytes. Incomplete
frames expire after a 200 ms read gap. UART reads and writes are nonblocking,
with bounded work per cycle and retries on transport errors.

Run parser tests from the repository root:

```sh
g++ -std=c++14 -Wall -Wextra -Werror -fsanitize=address,undefined \
    -fno-omit-frame-pointer \
    src/drivers/gas_sensor/ze07_h2/tests/protocol_test.cpp -o /tmp/ze07_protocol_test
/tmp/ze07_protocol_test
```

The tests cover the manual's literal example, all 30001 concentration values,
checksum corruption, unsupported headers, resynchronization, and resets.
On traced hosts where LeakSanitizer cannot run, use
`ASAN_OPTIONS=detect_leaks=0 /tmp/ze07_protocol_test`; address and undefined-behaviour
checks remain enabled.

A minimal host build can run the real UART/uORB driver against a pseudo-terminal:

```sh
cp src/drivers/gas_sensor/ze07_h2/tests/host.px4board boards/px4/sitl/ze07-default.px4board
cmake -S . -B build/ze07_host -G Ninja -DCONFIG=px4_sitl_ze07-default
cmake --build build/ze07_host -j4
python3 src/drivers/gas_sensor/ze07_h2/tests/integration_test.py build/ze07_host/bin/px4
```

CMake 4 may require `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` when configuring this
PX4 branch. The temporary SITL board configuration is only for these tests.
The integration test checks UART configuration, mode request, warm-up, ppm/H2/NaN
publication, corrupt/truncated packet rejection, stale timestamps, reconnection
warm-up, and start/stop behaviour. It uses the PX4 console directly and requires
no network or simulator.

Validation performed for this change: parser tests with ASan/UBSan, minimal PX4
POSIX build, UART/uORB pseudo-terminal tests, and serial startup/parameter generation
for the Pixhawk 6C port mapping. A complete NuttX/Pixhawk firmware build and physical
ZE07-H2 testing are still required before deploying to hardware.

Sources: [Winsen product page](https://www.winsen-sensor.com/product/ze07-h2.html),
[Winsen manual v1.0](https://www.winsen-sensor.com/d/files/manual/ze07-h2.pdf).
